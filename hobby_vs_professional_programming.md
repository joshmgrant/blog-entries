It's a new year, and I'm going to start off strong with a blog post. I thought I'd write about some loose thoughts I've had about professional versus hobby programming.

In case you've lived under a rock for the past year or so (and frankly I don't blame you), one of the newest trends in software development is ["vibe coding"](https://www.ibm.com/think/topics/vibe-coding). The main idea behind vibe coding is that instead of writing code directly, someone can use some AI assistant to generate code based on prompts. Now there's a whole range of vibe coding approaches, from someone with little to no programming knowledge treating the generated code almost like a black box and not even looking at it, to more [sophisticated approaches](https://simonwillison.net/2025/Dec/14/justhtml/) where experienced developers judiciously uses tools to write specific code with careful review. Since many AI tools are - for now - freely or cheaply available to almost anyone, there is a lot of experimentation going on with how to write code in various contexts using AI-assisted tools.

Based on the various stories of developers' experiences with vibe coding, I started thinking about using such tools in a professional setting versus in a hobby setting. I think the line between professional and hobbyist code is already blurry. There are numerous stories of developers turning their weekend projects into a paying job and beyond. As well, hobbyist developers sometimes use the same tools to work with code that experienced professionals do. Since a lot of AI tools are available for both serious and fun development work, I don't think that using such tools really differentiates hobby code from professional code at this time.

Here, I need to make a confession: I've been writing tiny little projects on my personal laptop purely for my own enjoyment, most of which _do not include any automated tests_. Yes, this is pure heresy from me, a seasoned SDET. But in a way, this adds to the fun of these toy projects. I write code that does one or two things, it works on my machine and needs to only ever work on my machine, the code sparks joy, and then I move on. Most of these projects are 100% never going to be production-grade projects, by design.

If I were writing production/professional code, what would be done differently?

For one, I'd be writing automated tests, since the code written would _need_ to work beyond my local workstation. Version control along with sensible practices would also be a requirement, something else I sometimes ignore when it comes to hobby projects. Code linting, compilation, type checking and other automated checks would also be required, likely set up not just to be executed locally but also within continuous integration. Interestingly, many tools like uv for Python automatically provide version control setup and provide some linting with a light lift. However, automated tests need to be created from scratch, even for small projects.

I've written before about how [automated tests are a feature](https://simplythetest.tumblr.com/post/793858685534437376/automated-tests-are-feature) that benefit developers working with a codebase. In the era of vibe coding, where creating code may have low or even zero cost, testing the code may become more important than ever. In a hobby setting, not having automated tests may be acceptable, maybe even preferable. In professional contexts, not having automated tests may soon be a non-starter.
